Project Overview & Vision
MUSIQA is a trilingual (Arabic/French/English) online music education platform targeting the Maghreb
region, starting in Tunisia. It addresses a structural gap in traditional conservatory education: fixed
schedules, geographic barriers, and the inefficiency of forcing students to learn during low-energy time
windows.
The platform delivers asynchronous video lessons, live 1-on-1 sessions with certified instructors, progress
tracking with gamification mechanics, and a community forum — all accessible from any device, at any
time the student chooses.
Pillar
Description
Flexibility
Learn any instrument or music production skill on any schedule, any device.
Quality
Curated, professional video content from vetted Tunisian and international
instructors.
Gamification
XP, streaks, badges and leaderboards keep students engaged and progressing.
Community
Forums, peer feedback, and collaborative challenges build social learning habits.
Scalability
Architecture designed from day one to support 100k+ concurrent users across
three countries.
Instrument & Discipline Coverage
String instruments: Guitar (classical, acoustic, electric), Oud, Violin, Bass
Keyboard: Piano, Synthesizer, Organ
Percussion: Drums, Derbouka, Bendir (traditional)
Wind: Flute, Saxophone, Trumpet
Voice: Classical singing, Pop vocal technique, Maqam vocal tradition
Music Production: DAW fundamentals, mixing, mastering, sound design (MAO)
Music Theory & Solfège: Written theory, ear training, harmony

3.1 Pre-Recorded Video Lessons
Course structure
Courses contain Sections > Lessons hierarchy. Each lesson has a video,
description, attachments.
Video player
Custom player with: playback speed (0.5x–2x), quality selector, subtitles/CC,

Offline mode
Mobile apps allow downloading lessons for offline viewing (DRM-protected).
Progress tracking
Auto-save progress at video position. Resume exactly where left off.
Attachments
PDF sheet music, guitar tabs, chord charts, practice backing tracks
downloadable per lesson.
Preview
First lesson of every course is free preview, no account required.
Search & filter
Full-text search by instrument, level (beginner/intermediate/advanced),
language, duration, rating.
Ratings & reviews
Students leave star rating + written review after completing 30% of a course.
3.2 Live 1-on-1 Sessions
Booking flow
Student browses instructor availability calendar → selects slot → pays →
receives confirmation + calendar invite.
Session room
WebRTC video call embedded in platform (no Zoom redirect). Both parties join
from browser or mobile app.
Session tools
Screen share, shared whiteboard, chat sidebar, file share during session.
Recording
Optional recording with consent from both parties. Stored 30 days,
downloadable by student.
Reminders
Email + push notifications 24h, 1h, 15min before session.
Cancellation policy
Configurable per instructor: free cancel > 24h before, partial refund 12–24h, no
refund < 12h.
Rating
Post-session rating for instructor (and optional student rating for instructors).
Trial sessions
Instructors can offer discounted 15-min intro sessions.

5
System Architecture
5.1 High-Level Architecture
MUSIQA follows a modular monolith architecture at launch (single NestJS codebase, cleanly separated
modules), with the database, cache, queue worker, and search index as separate services. This avoids
premature microservice complexity while maintaining a clear path to extract services if/when load
demands it.
CLIENT LAYER [Next.js Web App] [React Native iOS App] [React Native Android App] | | |
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■ HTTPS + WS ■■■■■■■■■■■■■■ | EDGE /
CDN LAYER | [Cloudflare] ← static assets, DDoS protection, rate limit at edge | | API
LAYER | [NestJS API Server]
■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■ | | | | | [PostgreSQL]
[Redis] [BullMQ Workers] [Meilisearch] [External APIs] (Prisma ORM) (Cache) (background
jobs) (search) Mux · Daily · Resend Stripe · Konnect
5.2 Module Breakdown (NestJS)
AuthModule — Registration, login, OAuth (Google), JWT refresh, OTP email verification
UsersModule — Profile management, avatar upload, roles, preferences, language
CoursesModule — CRUD for courses, sections, lessons, attachments, search index sync
VideoModule — Mux upload flow, webhook receiver, lesson video status management
EnrollmentsModule — Enrollment logic, access control, progress tracking, XP award
SessionsModule — Instructor availability, booking, Daily.co room creation, calendar invites
PaymentsModule — Stripe + Konnect integration, webhook handling, receipts, refunds
GamificationModule — XP engine, streak calculation, badge awards, leaderboard (Redis)
ForumModule — Threads, posts, replies, votes, audio uploads, moderation
NotificationsModule — Email (Resend), push (Expo), in-app notification feed (Socket.io)
AdminModule — Dashboard stats, user/content management, payout approval
SearchModule — Meilisearch indexing for courses, instructors, forum posts
5.3 Real-Time Events (WebSocket)
notification:new — push notification to connected client
session:countdown — countdown timer 5 min before live session
session:partner_joined — trigger UI state when other party connects
forum:reply — live reply append without page refresh
leaderboard:update — push leaderboard changes in real time

8
UI/UX Design Guidelines
8.1 Design Principles
Mobile-first — design every screen at 375px width first, scale up to desktop.
Clarity over cleverness — every UI element has an obvious purpose. No mystery icons.
Speed perception — skeleton loaders on every async component, optimistic UI updates.
Accessibility — WCAG 2.1 AA minimum. Sufficient contrast ratios, keyboard navigation, ARIA labels.
RTL-first for Arabic — layout, icons, text direction all switch correctly in Arabic mode.
Consistent micro-interactions — button presses, card hovers, success toasts all feel polished.
Zero dead-ends — every error state has a clear next action. No blank pages.

9
Internationalisation & RTL Support
9.1 Languages
The platform supports three languages from day one: Arabic (ar), French (fr), and English (en). Arabic is
the primary language for the Tunisian market and requires full RTL layout support. Language is
user-selectable in profile settings and persisted to the database.
9.2 Implementation
Use next-intl for Next.js — handles locale routing (/ar, /fr, /en prefix or cookie-based).
All translatable strings stored in /messages/ar.json, /messages/fr.json, /messages/en.json.
Database multilingual fields stored as separate columns (title_ar, title_fr, title_en) — simpler than
JSONB for querying.
RTL: add dir='rtl' to when locale is 'ar'. Use Tailwind's rtl: modifier for layout flips.
Font loading: load Cairo for Arabic locale, Inter for FR/EN — conditional in _document or layout.
Arabic numerals: respect user preference. Default to Eastern Arabic (■■■■) for ar locale unless user
overrides.
Date formats: DD/MM/YYYY for TN/DZ/MA. Use date-fns with locale import (ar-TN, fr, en).
Currency: TND (Tunisian Dinar) for Phase 1. Format: 1 500,000 TND style.
9.3 RTL Checklist for Developers
Navigation: logo on RIGHT in RTL, hamburger on LEFT
Text alignment: text-right in RTL (handled by dir attribute + Tailwind rtl:)
Icons with directionality (arrows, chevrons): flip horizontally in RTL
Progress bars: fill from RIGHT in RTL
Form fields: text input direction follows locale
Video player controls: mirror layout in RTL
Toast/notification position: bottom-left in LTR → bottom-right in RTL

10
Video & Streaming Infrastructure
All video content is hosted on Mux. The backend never handles raw video files — instructors upload
directly to Mux via a signed upload URL, keeping server load minimal.
10.1 Upload Flow
Step 1: Instructor clicks 'Upload Video' in course editor.
Step 2: Frontend calls POST /lessons/:id/upload-url → backend creates Mux Direct Upload URL.
Step 3: Frontend uploads video file directly to Mux using the signed URL (no backend proxy).
Step 4: Mux processes video (transcoding to HLS, generating thumbnails, running content
moderation).
Step 5: Mux fires video.asset.ready webhook → backend updates lesson with mux_asset_id and
mux_playback_id, sets status to 'ready'.
Step 6: Frontend polls lesson status or receives WebSocket push → shows video as available.
10.2 Playback & Security
Signed playback tokens — each playback URL is signed with JWT, expires in 12h, tied to user ID. No
public URLs.
HLS Adaptive Bitrate — Mux auto-generates 360p, 720p, 1080p variants. Player selects based on
connection.
DRM for downloads — Mux DRM (Widevine + FairPlay) protects offline downloads on mobile.
Watermarking — optional text watermark (student email) can be overlaid server-side via Mux overlays.
Completion tracking — player fires progress event every 30 seconds to POST /lessons/:id/progress.

11
Live 1-on-1 Session System
11.1 Booking Flow (Detailed)
Student selects instructor — From instructor profile, student opens availability calendar widget.
Slot selection — Calendar shows available 30/45/60-min slots (instructor-configured). Student picks
slot + duration.
Payment — Booking confirmation screen → payment flow (Stripe/Konnect). No booking without
payment.
Confirmation — On payment success: create live_sessions record, generate Daily.co room (via API),
send confirmation emails to both parties with calendar .ics attachment.
Reminders — BullMQ scheduled jobs send email + push at 24h, 1h, 15min before session.
Session time — Both parties see 'Join Session' button 10 min before scheduled time. Button fetches
Daily.co room token from backend (time-gated, tokens expire 2h after session start).
During session — Embedded Daily.co room with: video/audio, screen share, whiteboard, text chat,
file drop.
Post-session — Auto-expire room 15min after scheduled end. Trigger: rating prompt to student, XP
award, payout queue for instructor.
11.2 Instructor Payout
Platform takes 20% commission (configurable in admin). Instructor earns 80% of session price.
Payouts are batched weekly. Admin reviews payout queue and approves.
Payout methods: bank transfer (RIB) for TN, Wise for international instructors.
Instructor sees real-time earnings in dashboard: pending, approved, paid breakdown.

12
Payment & Monetisation
12.1 Payment Providers
Two providers are integrated. Stripe handles international cards. Konnect (Tunisian fintech) handles local
TND payments including Tunisian debit cards and mobile money. The platform detects user locale and
suggests the appropriate method.
12.2 Business Models (Design for All — Decide Later)
■ The business model is not finalised. The architecture supports all three without major refactoring.
Pay-per-course
Student pays once per course. Lifetime access. Simple, low friction. Price stored on courses.price. Check
enrollment record for access.
Subscription
Monthly/yearly plan unlocks all courses. Add subscriptions table (plan, status, stripe_subscription_id,
current_period_end). Access check: active subscription OR owned enrollment.
Freemium
Free tier: limited courses. Premium tier: all courses + discounts on live sessions. Same subscription table,
different plan slug.
Live sessions
Always pay-per-session regardless of subscription tier (sessions are instructor time, not platform content).

Store stripe_customer_id on users table after first payment. Reuse for future payments.
Subscriptions: use Stripe Billing with Products + Prices. Create in Stripe dashboard, reference Price ID

Security Requirements
Authentication & Authorisation
Passwords hashed with bcrypt (cost factor 12).
JWT access tokens expire in 15 minutes. Refresh tokens stored httpOnly Secure SameSite=Strict
cookie.
Refresh token rotation — every refresh issues a new refresh token and invalidates the old one (stored
in Redis with TTL).
Role-based guard on every route (student / instructor / admin). NestJS @Roles() decorator.
Email OTP verification required before account is active.
Rate limit auth endpoints: 5 login attempts per 15 min per IP (BullMQ + Redis).
API Security
Helmet.js — sets secure HTTP headers (CSP, HSTS, X-Frame-Options).
CORS — whitelist only known frontend origins (production domain + localhost in dev).
Input validation on every DTO with class-validator. No raw user input reaches the DB.
Parameterised queries via Prisma — no raw SQL string concatenation.
File upload validation: MIME type check server-side (not just extension), max size 500MB for video,
10MB for other assets.
Rate limiting: global 100 req/min per user, 20 req/min on write endpoints.
Data Privacy (GDPR-aligned)
Data minimisation — only collect what is needed.
Users can delete their account (soft delete, then hard delete after 30 days).
Payment data never stored on platform servers — Stripe handles PCI compliance.
Analytics: use PostHog with IP anonymisation enabled.
Cookie consent banner required on first visit.
Content Security
Video playback via signed tokens — no public HLS URLs.
User-uploaded audio in forum: scan with open-source audio fingerprinting to flag copyrighted content.
PDF/attachment downloads served via pre-signed R2 URLs (expire 1h).
Admin approval required before instructor courses go live.

Database
Add indexes on all foreign keys and frequently filtered columns (instrument, level, is_published).

Email sending (never block request on email send).
XP calculation and badge award after lesson completion.
